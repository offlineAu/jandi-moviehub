# Jandi MovieHub

**Your Movie Night. Everyone's Invited.**

Discover movies, stream authorized titles, and watch together in server-synchronized watch
parties with live chat, emoji reactions, and marathon playlists with intermissions and voting.

> Demo content: the four **Jandi Originals** are short films generated by this repository
> (`pnpm media:generate`) and are clearly labelled as demonstration media. Real public-domain and
> Creative-Commons titles appear with factual metadata only and are not playable until an
> administrator registers a media file under a verified license. Without a TMDB key the catalog
> runs in labelled "Demo catalog" mode.

## Quick start (local)

Prerequisites: Node ≥ 22.12 (24 recommended), pnpm 10 (`corepack enable`), PostgreSQL 16,
Redis 7+ — or Docker for the infrastructure (`docker compose up -d postgres redis mailpit`).

```bash
pnpm install
cp apps/api/.env.example apps/api/.env          # set MEDIA_SIGNING_SECRET (openssl rand -base64 48)
cp apps/web/.env.example apps/web/.env.local
createdb jandi_moviehub                          # or use the compose Postgres
pnpm --filter @jandi/shared build
pnpm db:deploy                                   # apply migrations
pnpm media:generate                              # render the demo films (~30 s, project-local ffmpeg)
pnpm db:seed                                     # catalog + register demo media
pnpm dev                                         # web http://localhost:3000 · API http://localhost:4000
```

If port 3000 is busy: `WEB_PORT=3300 pnpm --filter @jandi/web dev` and add
`http://localhost:3300` to `WEB_ORIGINS` in `apps/api/.env`.

Optional demo accounts (never admins): `SEED_DEMO_USERS=true SEED_DEMO_PASSWORD='<10+ chars>' pnpm db:seed`
→ `demo_alice`, `demo_bob`. Administrator:
`pnpm admin:bootstrap -- --email you@example.com --username you` (password from `ADMIN_PASSWORD`
or an interactive prompt). Development emails (verification, reset) are written to
`.data/mail/` and listed at `GET /api/v1/dev/mail`.

## What's inside

Administrators can manage series and episodes at `/admin/series`. At `/admin/sources`, they can
search Wikimedia Commons and save unverified video candidates for review. Saving a candidate
does not download it or make it playable: review its rights, register a license, upload an
authorized file, and approve its media asset through the admin tools.

|                   |                                                                                          |
| ----------------- | ---------------------------------------------------------------------------------------- |
| `apps/web`        | Next.js 16, React 19, Tailwind 4, Radix, TanStack Query — the UI                         |
| `apps/api`        | NestJS 11 REST + Socket.IO + BullMQ, Prisma/PostgreSQL, Redis                            |
| `packages/shared` | Zod schemas, realtime contracts, sync math shared by both                                |
| `docs/`           | architecture, API contracts (`docs/api`), decisions, security, deployment, test evidence |

API docs: http://localhost:4000/api/docs (OpenAPI) · realtime protocol: `docs/api/REALTIME.md`.

## Testing

```bash
pnpm lint && pnpm typecheck
pnpm test                 # unit tests (all packages)
pnpm test:integration     # API against real Postgres + Redis (isolated per run)
pnpm test:e2e             # Playwright: builds and starts an isolated stack on :3400/:4400
pnpm perf                 # performance measurements (see docs/TEST_RESULTS.md)
```

The integration and browser suites use separate PostgreSQL databases named
`jandi_moviehub_test` and `jandi_moviehub_e2e`. Create them before the first run, and configure
`apps/api/.env.test` by copying the API environment and setting `NODE_ENV=test`, the test
database URL, `REDIS_URL=redis://localhost:6379/1`, and a separate
`STORAGE_LOCAL_DIR=../../.data/test-storage`. Integration fixtures refuse to write to the normal
media directory. Generate the demo media before browser tests.
The browser suite starts its own servers and requires ports 3400 and 4400 to be free. Set
`E2E_REUSE_SERVERS=1` only when deliberately testing an already-running stack on those ports;
results from reused servers may reflect an older build.
